**Goal:** demonstrate that a managed C# 8086 core can execute a representative instruction subset **exactly** as
recorded on real hardware, and **measure** whether its speed meets NFR-002 and NFR-003.

**Scope (in):**
- A console project on .NET 10 (no UI): CPU state (registers, FLAGS), 1 MiB memory with 20-bit wrap, ModR/M
  decoding with segment defaults and overrides.
- Instructions: MOV (88–8B, B0–BF, C6/C7), ADD/SUB/CMP with flags (00–05, 28–2D, 38–3D, 80–83 /0 /5 /7),
  Jcc (70–7F), JMP short/near (EB, E9), CALL/RET near (E8, C3), PUSH/POP reg (50–5F), INT imm8 (CD) dispatched
  to a host hook.
- A test runner over the **SingleStepTests 8086** JSON cases for these opcodes (MIT; download the data to
  `poc/POC-001-cpu-core/testdata/` and record the source URL and commit). Undefined flags are masked with `flags-mask`.
- Measurements: (a) single step + full state snapshot latency, (b) free-run throughput on a tight loop. Record the
  machine spec as the first data point for OQ-014.

**Out of scope:** DOS services, UI, other opcodes, cycle timing, prefetch queue, snapshots for reverse stepping.

**Exit criteria (results recorded in this file as `[Measured]`):**
1. Pass rate per opcode against the SingleStepTests cases. Target: 100% for in-scope opcodes, and every failure explained.
2. Step + snapshot latency well below the NFR-002 budget (100 ms), with the measured value reported.
3. Throughput reported against the NFR-003 target (≥ 1,000,000 instructions/s).
4. Verdict: **feasible / feasible with changes / not feasible**. "Not feasible" triggers POC-005 (Spice86) for approval.

**Constraints:** no NuGet packages other than the JSON parsing in the base library (System.Text.Json) and, if needed, a test
framework. No GPL code or data. Tests must be deterministic and must not touch the network (the test data is downloaded once).

## Results (2026-10-26 18:32 +0500, Claude Code)

**Environment [Measured]:** Windows 11 Pro 10.0.26200, Intel Core i5-8265U @ 1.60 GHz (8 logical CPUs), 15.9 GB RAM, mains power,
Balanced power plan. .NET SDK 10.0.403 / runtime 10.0.14, Release build. This is the first data point for OQ-014, not a reference machine.

**Code:** `poc/POC-001-cpu-core/`. `Poc.Cpu` (core and oracle runner, no UI references), `Poc.Cpu.Tests` (xUnit v3 4.0.2),
`Poc.Cpu.Bench`. Test data: SingleStepTests 8086 v1 at commit `e71c68d215a6bb8c356bd4cb3842de3bef345ca9` (MIT), 89 opcode files
+ metadata, fetched by `fetch-testdata.ps1` and git-ignored.

### 1. Correctness against real hardware [Measured]
| Check | Result |
|---|---|
| `dotnet build Poc.Cpu.slnx -c Release` (warnings as errors, latest-recommended analyzers) | **0 warnings, 0 errors** |
| `dotnet test --solution Poc.Cpu.slnx -c Release` | **94/94 passed** (89 oracle files + 5 hand-written) |
| SingleStepTests cases (`--sst-report`) | **178,000 / 178,000 passed**: every in-scope opcode file, 2,000 cases each, all registers + all listed RAM + no unexpected writes |
| Opcodes covered | 00–05, 28–2D, 38–3D (ADD/SUB/CMP), 80/81/82/83 /0 /5 /7, 88–8B, B0–BF, C6/C7, 50–5F, 70–7F, E8, E9, EB, C3, CD (INT, real 8086 semantics), plus prefixes 26/2E/36/3E/F2/F3 as they occur in the data |
| Mutation check (PF logic deliberately inverted) | **31/94 failed**: exactly the 30 ADD/SUB/CMP oracle files + the hand-written ADD test. Restored afterwards, 94/94 pass. The oracle is not vacuous |
| Hand-written tests | ADD AL,BL flag example (AC-025), PUSH AX stack bytes (AC-026), unsupported opcode halts with CS:IP and bytes and keeps state (FR-037/AC-028), INT host hook (DOS integration point), deterministic trace over 150 steps (NFR-016) |

**Findings:**
- **C6/C7:** the data contains all ModR/M reg values /0–/7 (about 230–280 cases each). All pass with the reg field ignored, so on the 8086
  /1–/7 behave as /0. Metadata labels them "undefined", but the hardware behavior is consistent.
- **PUSH SP** (8086: pushes the decremented value), word access wrapping within the segment, and 20-bit address wrap are all exercised by the data and pass.

### 2. Step latency (NFR-002) [Measured]
Step + register snapshot over 200,000 steps (after warm-up): mean **0.091 µs**, p50 0.1 µs, p99 0.2 µs, max 627 µs (isolated OS/GC jitter).
The engine's share of the 100 ms budget is negligible; UI rendering will dominate. Stopwatch resolution is about 0.1 µs.
Worst-case snapshot (step + copying the full 1 MiB memory): **161 µs**. Affordable on demand, but reverse stepping (FR-060) should store diffs.

### 3. Throughput (NFR-003) [Measured]
Free run of an ADD/CMP/JNE loop, 3 × 50,000,000 instructions: **49.25, 47.71, 49.37 M instructions/s**, about 48× the ≥ 1 M/s target.
Caveat: the loop uses register-only instructions from the subset. Memory-heavy instructions, interrupt dispatch and UI throttling will
lower this, but the headroom is large.

### 4. Verdict
**Feasible.** A managed C# core reproduces real 8086 behavior exactly for the tested subset, is deterministic, and is orders of magnitude
faster than required. This supports R-ENG (custom core + SingleStepTests oracle). POC-005 (Spice86 fallback) is **not needed**.

**Inputs for the architecture phase:**
- The engine needs an interrupt interception point before vectoring (implemented here as `InterruptHook`) for the DOS layer.
- The test suite must run in **MTP mode** of `dotnet test` on the .NET 10 SDK: `global.json` `"test": {"runner": "Microsoft.Testing.Platform"}`.
  With xunit.v3 no VSTest adapter packages are needed. Without it, `dotnet test` fails with "Testing with VSTest target is no longer supported".
- Keep SingleStepTests data out of Git and fetch it pinned by commit. Decide in an ADR whether the product repo vendors a subset.
- Public-field register file: used here for the hot path with a scoped CA1051 suppression. Decide the product API in an ADR.
